The storage access control was already correctly implemented via delegation:
- ProjectStorageMixin.has_permission (base_models.py:897) delegates to
  project.has_permission(user)
- Project.has_permission (mixins.py:85) uses accessible_projects(user) from T4
- HasObjectPermission (api_permissions.py) calls obj.has_permission(user)
- DRF's check_object_permissions is called automatically for detail views

The only improvement made was consistency: the List APIs now use
get_permitted_project() which raises 404 for inaccessible projects (instead of
loading the project and then checking permissions, which could leak existence).

All other endpoints (Detail, Sync, Resolve) already had proper object-level
permission checks via DRF's automatic check_object_permissions or explicit
instance.has_permission() calls.
