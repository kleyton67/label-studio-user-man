5. RISKS
--------------------------------------------------------------------------------
- IsOrganizationAdmin gates on request.user.has_perm('users.manage'), which the
  T2 rules backend resolves via is_org_admin (is_superuser OR is_admin OR active
  org creator). This is the intended admin definition for this plan; a plain
  member is denied. No change to that logic was made here.
- Duplicate POSTs always return 201 (idempotent in effect: no second row). If a
  client strictly expects 200 for an already-existing link, that is a contract
  choice to revisit in the frontend task; the plan only requires "ignore
  duplicates".
- `UserGroupMemberSerializer.user` and `UserGroupProjectSerializer.project` are
  writable pk fields; the org-membership / org-ownership validation lives in the
  view (not in the serializer), so the error is a 400 ValidationError with a
  field-specific message.
- No pagination on the group/member/project lists (matches the plain-list
  behaviour of other admin-ish endpoints here); PAGE_SIZE is not applied because
  DEFAULT_PAGINATION_CLASS is unset. If lists grow large, add pagination later.
- Manual QA used a throwaway sqlite DB and was torn down; nothing persists.
