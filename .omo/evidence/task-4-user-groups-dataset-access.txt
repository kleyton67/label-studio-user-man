5. RISKS
--------------------------------------------------------------------------------
- Behavioral change: T4 changes the default from "all org members see all projects"
  to "only group members see granted projects". This is the INTENDED restrictive
  behavior (IS-4, IS-5). Existing tests that assumed the old behavior were updated
  (test_models.py, data_manager/tests/test_api.py). Any production deployment must
  run the T3 backfill migration first to create default groups with all members
  and projects, otherwise users will lose access.

- Circular import avoided: ProjectManager.for_user imports accessible_projects
  inside the method (not at module load) because access.py imports Project at
  module load. This is documented in the code comment.

- organization is None case preserved: has_permission returns True if
  organization_id is None (legacy rows, tests). accessible_projects returns
  Project.objects.none() if user.active_organization is None. Both behaviors
  are tested.

- Admin bypass: is_admin_user checks superuser, is_admin flag, and org owner.
  All three paths are tested. Admins see all org projects regardless of group
  membership.

- Soft-delete respected: accessible_projects checks organization.has_deleted(user)
  and returns Project.objects.none() if true. Tested.
